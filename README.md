# The City Property

نظام إدارة عقارات احترافي (Flutter + Supabase) بواجهة عربية RTL كاملة، يدعم ثلاثة أدوار: **المالك**، **مدير العقارات**، و**المستأجر**. التطبيق يعمل على Android وiOS (وWeb للاختبار السريع).

## الميزات

### المالك
- لوحة نظرة عامة: نسبة الإشغال، الإيجار المتوقع والمحصل، المتأخرات، الطلبات المعلّقة.
- محفظة العقارات: المجمعات → المباني → الطوابق → الشقق، مع بحث وتفاصيل كل مبنى.
- احتفال بصري ذهبي عند اكتمال إشغال مبنى بالكامل.
- الموافقة على تكاليف الصيانة أو رفضها مع سبب، ومتابعة التنفيذ.
- المالية: تحصيل 6 أشهر، حالة دفع المستأجرين، وسجل الدفعات.

### مدير العقارات
- لوحة متابعة، طلبات مرتبة حسب الأولوية، وفلترة حسب مرحلة العمل.
- تسجيل دفعات الإيجار نيابة عن المستأجر.
- إدارة المستأجرين وإضافة مستأجر جديد مباشرة على شقة فارغة.
- مراجعة طلبات ربط المستأجرين بالشقق (قبول/رفض).
- إرسال تكلفة تقديرية للمالك، بدء العمل، وإنهاء العمل مع التكلفة النهائية.

### المستأجر
- تسجيل الدخول برقم الهاتف + كلمة المرور (والتحقق برمز OTP أثناء إنشاء الحساب فقط).
- ربط الشقة ذاتياً بطلب يُعرض على المدير للموافقة.
- شريط عدّ تنازلي حتى موعد الإيجار القادم.
- إنشاء طلب صيانة (كهرباء، سباكة، إنترنت...) مع صور أو لقطات محادثة.
- متابعة مراحل الطلب والتواصل عبر محادثة الطلب.
- سجل الدفعات وتعليمات الدفع والتواصل مع المدير.

## التشغيل السريع

```bash
flutter pub get
flutter run                 # يقرأ env.dev
```

للبناء بأعداد الإنتاج:

```bash
flutter build apk --release --dart-define=PROD=true
flutter build ios --release --dart-define=PROD=true
```

> `PROD=true` يجعل التطبيق يقرأ `env.prod`.

## إعداد Supabase

1. أنشئ مشروع Supabase وضع عنوان المشروع والمفتاح في `env.dev` / `env.prod`:
   ```dotenv
   SUPABASE_URL=https://<project>.supabase.co
   SUPABASE_ANON_KEY=<publishable-key>
   ```
2. نفّذ الملف [`supabase/schema.sql`](supabase/schema.sql) في **SQL Editor**. الملف idempotent ويضيف:
   - أعمدة `image_urls`, `manager_notes`, `rejection_reason` لطلبات الصيانة.
   - جدول `maintenance_messages` + فهارس + سياسات RLS.
   - Bucket التخزين `maintenance` وسياسات الرفع/القراءة/الحذف.
   - دالة `manager_add_tenant` التي تنشئ حساب Auth (هاتف + كلمة مرور) + بروفايل + عقد + ربط الشقة في معاملة واحدة (لأن `profiles.id` مرتبط بـ `auth.users`).
   - تقوية المصادقة: `handle_new_user`، `ensure_profile`، `claim_role`، وسياسات RLS مرتبطة بالعلاقات فقط.
3. تأكد من وجود الجداول الأساسية: `profiles`, `compounds`, `buildings`, `floors`, `apartments`, `leases`, `tenant_apartments`, `payments`, `manager_assignments`, `maintenance_requests`.
4. فعّل مزوّد الهاتف في **Authentication → Providers → Phone** واربطه بمزود SMS (مثل Twilio) لأن رمز التحقق يُرسل عند التسجيل.

## المصادقة

- **تسجيل الدخول**: رقم هاتف عراقي (`07xxxxxxxxx`) + كلمة مرور، دون رمز OTP في كل مرة.
- **إنشاء حساب**: الاسم + الهاتف + كلمة مرور (٨ أحرف على الأقل) ثم رمز تحقق SMS لمرة واحدة.
- **الدور الافتراضي**: كل حساب جديد يُنشأ **مستأجراً** على مستوى قاعدة البيانات. المالك والمدير يحتاجان رمز دعوة يُتحقق منه داخل `claim_role` من جدول `app_config` (لا يُخزَّن الرمز في التطبيق).
- **حساب المستأجر من المدير**: شاشة «إضافة مستأجر» تنشئ حساب الدخول مباشرة بهاتف المستأجر وكلمة مرور مؤقتة يشاركها المدير معه.

لتغيير رموز الدعوة نفّذ في SQL Editor:
```sql
update public.app_config set value = 'رمز-المالك-الجديد' where key = 'owner_invite_code';
update public.app_config set value = 'رمز-المدير-الجديد' where key = 'manager_invite_code';
```

> بدون مزوّد SMS مضبوط سيفشل إنشاء الحساب برسالة واضحة. هذا قيد خارجي في Supabase ولا يمكن تجاوزه برمز ثابت داخل التطبيق.

## سير عمل الصيانة

```
المستأجر ينشئ الطلب + صور
        ↓
المدير يحدد التكلفة التقديرية وملاحظات
        ↓
المالك يوافق / يرفض (مع سبب)
        ↓
موافقة → المدير يبدأ العمل → يكمل مع التكلفة النهائية
رفض   → لا يبدأ العمل، ويبقى السبب ظاهراً للطرفين
```

كل طلب له محادثة مستقلة بين المستأجر والمدير والمالك، وتظهر الصور داخل تفاصيل الطلب.

## البنية

```
lib/
  app/           نقطة الإقلاع، الحراسات، مزودات Riverpod
  core/          الثيم، الأدوات، الويدجت المشتركة، الرسوم
  data/          الموديلات، Supabase Repository، خدمة المصادقة
  features/
    auth/        الدخول، OTP، إعداد الملف
    owner/       لوحة المالك، الموافقات، المالية
    manager/     لوحة المدير، الطلبات، المستأجرون
    tenant/      الرئيسية، الطلبات، الدفعات، ربط الشقة
    shared/      تفاصيل الطلب، المحفظة، تفاصيل المبنى، الملف الشخصي
supabase/
  schema.sql     ترحيل الإكمال + سياسات RLS + التخزين
legacy/          شاشات قديمة مؤرشفة (خارج lib) للرجوع إليها
```

## الأمان

- لا توجد رموز تجريبية أو مسارات كتابة بدون جلسة في التطبيق؛ كل العمليات تمر بجلسة Supabase حقيقية.
- استخدم مفاتيح `publishable`/`anon` فقط داخل التطبيق، ولا تضع `service_role` أبداً.
- RLS مفعّل على جداول Supabase أو يجب تفعيله، والسياسات مرتبطة بالعلاقات (مالك/مدير/مستأجر) لا بالأدوار وحدها.
- كل حساب جديد يبدأ مستأجراً؛ ترقية الدور تحتاج رمز دعوة يُتحقق منه على الخادم، ولا يمكن للمستخدم تعديل دوره أو هاتفه من التطبيق.
- Bucket الصور عام للقراءة كي تُعرض الروابط مباشرة. للخصوصية الكاملة: اجعل الـ bucket خاصاً وحوّل التطبيق إلى `createSignedUrl`.
